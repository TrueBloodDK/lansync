# Первый сетевой обмен

Команда `serve` публикует папку только для чтения. Команда `pull` выполняет
однократное скачивание новых файлов и создаёт каталоги. Это ещё не двусторонняя
синхронизация: существующий отличающийся файл — конфликт, удаления не применяются.
Совпадающие по SHA-256 файлы повторно не передаются. Для начала используйте пустую
папку назначения. Сервер перечитывает папку при каждом запросе манифеста;
предварительно запускать `watch` или `scan` не требуется.

## Подготовка

Из папки проекта обновите установку:

```powershell
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
```

`trustme` из набора dev нужен только для создания демонстрационных сертификатов
и тестов; готовые PEM-сертификаты можно использовать без этой зависимости.

Создайте сертификат для IP сервера. Ниже `192.168.1.10` — пример, замените его
на реальный IP. Для проверки на одном компьютере достаточно `--host 127.0.0.1`.
Каталог с ключами должен быть новым и находиться вне общей папки:

```powershell
.\.venv\Scripts\python.exe scripts/create_credentials.py --host 127.0.0.1 --host 192.168.1.10 --output-dir "C:\Users\dkara\Documents\lansync-credentials"
```

Будут созданы `token.txt`, `ca.pem`, `server.pem`, `server-key.pem`.
Скрипт не перезаписывает существующий каталог. Клиенту передайте только
`token.txt` и `ca.pem` доверенным способом. Приватный ключ остаётся на сервере.
Токен даёт доступ ко всем опубликованным файлам; индивидуальных пользователей
и отзыва отдельных устройств пока нет. Храните каталог ключей в личном профиле.

## Сервер

В первом терминале (общая папка уже должна существовать):

```powershell
.\.venv\Scripts\lansync.exe serve "C:\Users\dkara\Documents\Shared" --state-dir "C:\Users\dkara\Documents\lansync-state" --host 0.0.0.0 --port 8765 --token-file "C:\Users\dkara\Documents\lansync-credentials\token.txt" --cert-file "C:\Users\dkara\Documents\lansync-credentials\server.pem" --key-file "C:\Users\dkara\Documents\lansync-credentials\server-key.pem"
```

`0.0.0.0` означает приём соединений на всех IPv4-интерфейсах; для проверки
на одном компьютере используйте `--host 127.0.0.1`. Если подключаетесь с другого
компьютера, разрешите входящий TCP-порт 8765 для частной сети в брандмауэре.
Остановка — `Ctrl+C`. Можно добавлять `--exclude "*.tmp" --exclude ".git"`.
Не запускайте `watch` и `serve` с одной папкой состояния одновременно.

## Клиент

Создайте отдельную папку назначения и во втором терминале запустите:

```powershell
New-Item -ItemType Directory -Force "C:\Users\dkara\Documents\Received"
.\.venv\Scripts\lansync.exe pull https://127.0.0.1:8765 "C:\Users\dkara\Documents\Received" --token-file "C:\Users\dkara\Documents\lansync-credentials\token.txt" --ca-file "C:\Users\dkara\Documents\lansync-credentials\ca.pem"
```

На другом компьютере замените URL на `https://192.168.1.10:8765`, укажите
локальные пути к скопированным токену и сертификату CA. Адрес в URL должен
присутствовать в сертификате. На Linux команды те же, с Linux-путями и
`lansync` из активированного окружения.

Ожидаемый результат: `Downloaded: N; unchanged: 0`, при повторном запуске —
`Downloaded: 0; unchanged: N`. При изменении существующей локальной копии
команда остановится с `Local conflict`, сохранив её содержимое.
Код завершения — 0 при успехе, 1 при ошибке. После ошибки уже полностью
скачанные файлы остаются, незавершённый временный файл удаляется; повторите `pull`.

Для разработки разрешён HTTP только на буквальных loopback-адресах `127.0.0.1`
и `::1`, при явном `--allow-http` у сервера и клиента. Передача по локальной
сети требует HTTPS; отключения проверки сертификата нет.

## Протокол и ограничения

- `GET /v1/manifest`: полный манифест версии 2, только после авторизации.
- `GET /v1/file?path=...&sha256=...`: файл из опубликованного манифеста.
- Заголовок `Authorization: Bearer <token>` обязателен для обоих запросов.
- 401 — неверный токен; 400 — недопустимый путь; 404 — файл не опубликован;
  409 — источник изменился или манифест неполон. При 409 повторите `pull`
  после устранения причины; `scan` покажет ошибки источника.

Сервер создаёт временную дисковую копию и проверяет её хеш до ответа, поэтому
на сервере нужно свободное место размером с передаваемый файл для каждого
одновременного скачивания. Клиент читает блоками до 1 МиБ, проверяет размер
и SHA-256, затем публикует временный файл без замены существующего. В Windows
используется rename без замены, в POSIX — hard link; файловая система клиента
должна поддерживать эту операцию. Права, владельцы и время изменения не переносятся.

Клиент проверяет весь манифест до записи: допустимые пути, имена, коллизии,
типы, размеры, хеши, иерархию и локальные конфликты. Максимальный размер JSON —
16 МиБ. Ссылки и Windows reparse points не допускаются на путях передачи.
Текущая проверка путей рассчитана на доверенные локальные каталоги: она не
обеспечивает защиту от другого локального процесса, намеренно подменяющего
родительские каталоги во время операции. Не используйте корень файловой системы
или каталоги, доступные для записи недоверенным пользователям.

Источник может меняться между запросами; это не атомарный снимок всей папки.
Различающиеся существующие файлы не обновляются автоматически до появления
базовых ревизий и политики конфликтов. Отправки на сервер, синхронизации удалений,
возобновления с конкретного байта и фонового сетевого цикла пока нет.

Использованы [StreamingResponse FastAPI](https://fastapi.tiangolo.com/advanced/custom-response/)
и [проверка TLS HTTPX](https://www.python-httpx.org/advanced/ssl/).
