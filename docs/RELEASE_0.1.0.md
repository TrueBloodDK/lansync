Исходники пакетов: `68ff27d53ad7f631366768742bdc0dcd9ecfb717`.
Поддерживаемые роли: сервер Linux, клиенты Linux и Windows. Требуется Python 3.11+;
фактическая финальная проверка — Python 3.14.8 на CachyOS и 3.12.14 на Windows 11.

## Проверки

- Полный набор unit-тестов: Linux 127 прошли; Windows 119 прошли, 8 POSIX пропущены.
- Wheel собран через sdist; чистая установка Linux, pip check и 13 HTTPS-сценариев
  прошли. Проверены конфликты, обе версии, удаления, reconnect и штатная остановка.
- На Windows проверена чистая установка **того же wheel**, pip check, CLI, создание
  проекта, реквизиты, TOML и scan. SHA-256 wheel и sdist совпадают в обоих отчётах.
- Из установленных wheel выполнен обмен test1 → test2 и обратно: 320 МиБ
  (64 + 256 МиБ) в каждом направлении; времена 6,084 и 3,358 с, хеши совпали.
- Linux-сервер и Windows-клиент из этого wheel прошли 8 сетевых сценариев:
  TLS/doctor, Unicode и пустые объекты, бинарный файл 4 МиБ с проверкой SHA-256,
  изменения в обе стороны, dry-run и удаления, разрешение конфликта,
  целостность recovery Windows и Linux. Тестовые серверы остановлены,
  временные правила UFW удалены; исходное разрешение SSH сохранено.
- Двухчасовой прогон, ENOSPC, SIGKILL и poweroff ВМ описаны в
  [отчёте устойчивости](RESILIENCE_20261115.md). Код `src/lansync` после этих
  испытаний не менялся; коммит выпуска добавляет документацию и проверку пакетов.

Версии фактически установленных зависимостей сохранены в JSON-отчётах.

## Известные границы

Автозапуск Linux после перезагрузки проверен. На Windows проверен ручной запуск
задания Планировщика, но не настоящий выход/вход пользователя. Настройка такого
развёртывания требует отдельной приёмки; обычный запуск клиента этим не ограничен.
После аварии lock/pending могут потребовать ручной проверки и восстановления.
Автоматический ремонт не реализован. На Windows нет fsync каталогов через этот API.
Физическое обесточивание хоста не проверялось. Сетевые ВМ находились на одном хосте.

GUI развивается поверх этого выпуска: [границы интеграции](GUI_INTEGRATION.md).
Новая версия с изменённым ядром должна снова проходить приёмку; результаты 0.1.0
не переносятся автоматически на будущие изменения.
