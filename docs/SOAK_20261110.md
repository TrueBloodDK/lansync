# Нагрузочный прогон 9–10 ноября 2026

На test1 (192.168.0.108) и test2 (192.168.0.109) запущен новый scripts/soak.py
с CLI из репозиториев на 96970eb. Новые сценарии переданы отдельно, исходники
приложения на ВМ не изменялись. Прогоны выполнялись параллельно на одном физическом
компьютере. Это отдельные сервер и клиент через loopback внутри каждой ВМ,
а не измерение сети между ВМ.

На каждой стороне начальное дерево — 500 файлов по 4096 байт; крупные файлы
переданы в обе стороны и оставлены в дереве для последующих полных обходов.
Пять минут повторных изменений не включают подготовку и крупные передачи.

| Показатель | test1 | test2 |
|---|---:|---:|
| Размер крупного файла в каждом направлении | 64 МиБ | 128 МиБ |
| Продолжительность серии | 300,66 с | 301,46 с |
| Операций изменения/удаления | 228 | 205 |
| В том числе удалений | 22 | 20 |
| Медиана ожидания изменения | 1,24 с | 1,34 с |
| Максимум ожидания изменения | 2,51 с | 2,63 с |
| Загрузка крупного файла с сервера | 1,93 с | 4,35 с |
| Передача крупного файла на сервер | 1,98 с | 2,55 с |
| Проверено recovery на сервере / клиенте | 94 / 94 | 84 / 84 |

Оба результата — passed. После штатного SIGTERM код клиента 0, sync.lock
отсутствует, статус stopped. Итоговые деревья совпали по SHA-256 и каталогам;
проблем целостности recovery не обнаружено. Процессы стенда остановлены.

## Память

RSS считывался каждые 0,5 секунды из /proc. За начало сравнения взята первая
выборка после 60 секунд от запуска процессов, за конец — последняя до выхода клиента.

| Процесс | RSS на 60-й секунде | RSS в конце | Максимум среди выборок |
|---|---:|---:|---:|
| test1 сервер | 69,60 МиБ | 69,66 МиБ | 71,26 МиБ |
| test1 клиент | 65,51 МиБ | 68,50 МиБ | 70,49 МиБ |
| test2 сервер | 68,51 МиБ | 68,56 МиБ | 70,19 МиБ |
| test2 клиент | 65,22 МиБ | 68,43 МиБ | 70,42 МиБ |

RSS клиентов вырос примерно на 3 МиБ. Этот прогон не позволяет отличить удержание
памяти аллокатором от накопления объектов; отсутствие утечек не подтверждено.
Следующий шаг — длительный прогон с профилированием при продолжающемся росте.
Выборочные пики могут пропустить кратковременный максимум.

## Дополнительные проверки сценария

Прошли короткий запуск (10 файлов, по 1 МиБ в обе стороны, 5 секунд изменений),
минимальная положительная duration (выполняется хотя бы одна операция),
отказ от NaN без создания output, отчёт failed при неработающем CLI,
отказ от перезаписи существующего output. В CI добавлен короткий Linux-прогон;
удалённый GitHub Actions в рамках этой работы не запускался.

Сырые отчёты на ВМ: ~/lansync-soak-extended-20261109/verification.json.
Результаты и журналы оставлены вместе с тестовыми проектами; весь каталог
содержит секреты тестового стенда и не предназначен для публикации.

Пять минут не заменяют многочасовой прогон. Задержки включают опрос, сканирование,
хеширование и запись состояния; это не чистая пропускная способность LAN.
Конкурентное редактирование, автозапуск после перезагрузки и аварийное
восстановление здесь не проверялись.
