# Передача крупных файлов по сети, 10 ноября 2026

Новый scripts/lan_benchmark.py проверен с сервером test1 (192.168.0.108,
CachyOS) и двумя клиентами: test2 (192.168.0.109, CachyOS) и Windows-хостом
(192.168.0.102). CLI на ВМ — 96970eb; Windows использует рабочее окружение
репозитория на daf7ec6. Изменений кода приложения между этими коммитами нет:
добавлялись сценарии испытаний и документация.

Для каждого клиента создан отдельный серверный проект, отдельные сертификаты
с IP сервера и новый клиентский проект. На сервере работают временные
пользовательские службы systemd; HTTPS слушает конкретный IP, не loopback.
UFW временно разрешал 8877 только от test2 и 8878 только от Windows-хоста.

Набор в каждом направлении: два сгенерированных файла, 64 и 256 МиБ,
всего 320 МиБ. Измерялся один проход синхронизации на направление, включая
обход, SHA-256, TLS, запись файлов и состояния. Генерация исходных файлов
не входит во время прохода. Кеши не очищались.

| Клиент | Направление | Объём | Время | Эффективная скорость |
|---|---|---:|---:|---:|
| Linux test2 | Сервер → клиент | 320 МиБ | 4,917 с | 65,08 МиБ/с |
| Linux test2 | Клиент → сервер | 320 МиБ | 6,808 с | 47,00 МиБ/с |
| Windows | Сервер → клиент | 320 МиБ | 7,390 с | 43,30 МиБ/с |
| Windows | Клиент → сервер | 320 МиБ | 3,172 с | 100,88 МиБ/с |

Оба результата — passed. Проверены независимые SHA-256 локальных файлов
и хеши нового манифеста сервера после загрузки. Нет конфликтов, обратных
неожиданных передач или удалений. Блокировка клиентского состояния освобождена.

Повторный запуск с прежним fixture на уже изменённом сервере завершился отказом
до синхронизации: клиентская shared осталась пустой, baseline не создан.
Дополнительно прошли два unit-теста проверки путей/метаданных fixture и требований
к серверному манифесту. Компиляция скрипта и git diff --check прошли.

В конце обе временные службы остановлены. Правила UFW для 8877/8878 удалены;
проверены исходные разрешения только для SSH и отсутствие слушателей на тестовых
портах. Приватные серверные ключи клиентам не передавались.

## Границы результата

Использованы разные узлы и IP-адреса с сетевым мостом VirtualBox, но обе ВМ
работают на том же физическом компьютере, что и Windows-хост. Виртуальный коммутатор
может передавать трафик внутри хоста. Это не замер физического Ethernet/Wi-Fi
между двумя отдельными компьютерами и не характеристика сетевого адаптера.
По одному проходу нельзя делать вывод, что одна ОС быстрее другой.

Серверы и клиенты для этого теста не работали непрерывно; многочасовой прогон,
автозапуск при перезагрузке и аварийное восстановление этим тестом не закрываются.

Сырые отчёты: на test2 — ~/lansync-lan-client-20261110/verification.json;
на Windows — outputs/lan-benchmark-20261110/linux.json и
outputs/lan-benchmark-20261110/windows-client/verification.json в рабочем каталоге.
Тестовые проекты оставлены; их каталоги содержат секреты и не публикуются целиком.
