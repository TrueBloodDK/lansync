# Первый запуск LANSync

GUI — клиент для Windows и Linux. Сервер запускается отдельно на Linux.
Для переносимого клиента Python устанавливать не нужно. На Linux требуется
графическая сессия и совместимые системные библиотеки Qt; проверенный стенд — CachyOS.

## Установка и подключение

1. Распакуйте **весь** архив в постоянную папку. На Windows запустите `LANSync.exe`,
   на Linux — `LANSync`. Каталог `_internal` должен оставаться рядом с программой.
2. Получите у администратора HTTPS-адрес сервера с портом и папку клиентских
   реквизитов: `ca.pem` и `token.txt`. Приватный ключ сервера клиенту не нужен.
   Настройка собственного сервера описана в [INSTALL.md](../INSTALL.md).
3. Нажмите «Новый проект…». Укажите новую папку проекта, адрес сервера и папку
   реквизитов. Для первого знакомства оставьте «Папка файлов» пустой: мастер
   создаст `shared` внутри проекта. Для своей папки файлов разместите проект
   вне неё на том же диске. Проект храните отдельно от папки приложения.
4. Нажмите «Создать проект», затем «Проверить соединение». При ошибке прочтите
   пояснение под статусом и журнал. Проверьте адрес, службу сервера и доступность
   его порта от клиента; не отключайте проверку сертификата.
5. Нажмите «План изменений» и просмотрите ожидаемые действия. Создание проекта
   и просмотр плана сами по себе не переносят файлы.
6. Нажмите «Синхронизировать» для одного прохода или «Запустить постоянно»
   для наблюдения за папкой и регулярных сверок с сервером.

Синхронизация двусторонняя: изменения и удаления распространяются на другую
сторону. План показывает состояние на момент проверки; запуск заново проверяет
файлы, поэтому результат может отличаться, если файлы успели измениться.

## Повседневная работа

«Синхронизировано» означает успешный проход. Проверяйте также время последнего
успеха: этот статус не гарантирует, что сервер доступен прямо сейчас.
«Повтор подключения» означает, что постоянный режим ждёт восстановления связи.
После запуска сервера он продолжит работу автоматически. Если ожидание затянулось,
проверьте питание ВМ, службу сервера, IP-адреса и правила межсетевого экрана.

«Остановить» завершает текущую операцию безопасно; дождитесь остановки перед
переключением проекта. «Свернуть в трей» оставляет приложение работающим.
Для фоновой работы после входа откройте «Автозапуск…» и выберите нужный режим.
После перемещения приложения обновите автозапуск, иначе он будет ссылаться
на старое расположение. Обычное открытие проекта не запускает синхронизацию.

## Если обе стороны изменили один файл

Остановите постоянный режим. Во вкладке «Конфликты» нажмите «Обновить», выберите
строку и нужную версию. Если конфликт ещё не зарегистрирован, сначала выполните
«Синхронизировать». «Сохранить обе» оставляет серверную версию по исходному пути,
а локальную сохраняет под новым относительным именем. Укажите свободное имя
в существующей папке. Прочитайте подтверждение: выбор запускает полный проход
синхронизации, который может затронуть и другие изменённые файлы.

## Резервные копии и диагностика

Во вкладке «Резервные копии» нажмите «Обновить», проверьте записи, выберите нужную
и экспортируйте её в **новый файл вне папки синхронизации и состояния**.
Экспорт не заменяет текущий файл: сначала сравните содержимое и только затем
при необходимости верните его в общую папку.

При ошибке сохраните журнал кнопкой «Сохранить журнал…» в новый файл вне проекта.
Журнал может содержать пути и имена файлов. При сообщениях о блокировке состояния
или незавершённой операции не удаляйте служебные файлы: порядок проверки описан
в [SYNC.md](../SYNC.md). Не запускайте CLI и GUI одновременно для одного состояния.

Для обновления остановите клиент, закройте его, распакуйте новую сборку отдельно
и откройте прежний `project.toml`. Сохраните папку проекта целиком: кроме файлов
она содержит историю, реквизиты и резервные копии.

Подробности и границы проверок: [GUI.md](GUI.md).
Показ научруку: [GUI_DEMO.md](GUI_DEMO.md).
