# Демонстрация графического клиента за 10–15 минут

Стенд: Linux-сервер и Windows- или Linux-клиент с готовой сборкой LANSync.
Две ВМ или хост и ВМ подходят: данные передаются по HTTPS, общие папки VirtualBox
для обмена не используются. Для показа возьмите отдельный тестовый проект.

## До встречи

Запустите сервер, проверьте адрес и порт, подготовьте клиентский комплект
`ca.pem` / `token.txt`. Создайте клиент через [краткую инструкцию](GUI_QUICKSTART.md).
Откройте рядом папку сервера, папку клиента и окно LANSync. Остановите постоянный
режим. Подготовьте обычный текстовый редактор на обеих машинах. Используйте
свободное имя `demo-notes.txt`; не редактируйте чужие файлы ради показа.

## Ход показа

| Шаг | Действие | Что показать |
| --- | --- | --- |
| Подключение | Нажать «Проверить соединение» | Успешная HTTPS-проверка и адрес сервера |
| План | Создать `demo-notes.txt` на сервере, нажать «План изменений» | Запланированное получение; файла на клиенте ещё нет |
| Обмен | Нажать «Синхронизировать» | Файл появился на клиенте, содержимое совпадает |
| Наблюдение | Включить постоянный режим, изменить файл на клиенте | Изменение появилось на сервере, обновилось время успеха |
| Конфликт | Остановить клиент, записать разные тексты в этот файл на каждой стороне, запустить один проход | Обнаружен конфликт; версии не затёрты молча |
| Решение | Обновить вкладку «Конфликты», выбрать «Сохранить обе», указать `demo-notes-local.txt`, подтвердить | На обеих сторонах доступны исходное имя с серверным текстом и новая копия с локальным |
| Восстановление | Обновить «Резервные копии», выбрать проверенную запись и экспортировать в новый файл вне проекта | Можно прочитать прежнюю версию без замены текущего файла |

После разрешения конфликта выполните ещё один проход и сравните оба файла.
Для демонстрации восстановления используйте запись, соответствующую показанному
файлу; если её нет, измените серверную версию после успешной сверки и получите
её клиентом — предыдущая локальная версия должна попасть в recovery.

## Дополнительный показ устойчивости

Если остаётся время, включите постоянный режим, штатно остановите службу сервера
и дождитесь сообщения о повторе подключения. Затем запустите службу и покажите
новое время успешной синхронизации. Не выключайте питание ВМ: это отдельный
аварийный сценарий, а не имитация временной недоступности сервиса.

Автозапуск после входа лучше показать отдельной короткой записью экрана:
сохранить работу, выйти из учётной записи с работающим клиентом, войти снова,
проверить появление окна и новый успешный проход. На Windows сначала штатно
остановите гостевые ОС, если выход завершит VirtualBox; после входа запустите их.

Для отчёта сохраните версии сборок, ОС, схему сети, несколько снимков с состояниями
и журнал. Не включайте содержимое `token.txt` и приватный ключ сервера.
