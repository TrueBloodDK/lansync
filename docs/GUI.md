# GUI-клиент 0.2.0.dev3

Первый рабочий интерфейс на PySide6/Qt Widgets. Это версия для разработки;
проверенный CLI-выпуск 0.1.0 остаётся отдельным неизменным архивом.
Ядро синхронизации используется напрямую, серверный протокол не менялся.

## Запуск из репозитория

Из активированного Python-окружения:

```sh
python -m pip install -e ".[gui]"
python -m lansync.gui
```

Также устанавливается команда `lansync-gui` для запуска без консоли на Windows.
Можно сразу открыть проект: `python -m lansync.gui --config /path/to/project.toml`.
PySide6 — дополнительная зависимость; обычному CLI она не нужна.

Выберите существующий клиентский `project.toml` (command = "sync"). Проект должен
иметь локальную папку, каталог состояния вне неё и реквизиты подключения.
Подготовка проекта и клиентского комплекта описана в [INSTALL.md](../INSTALL.md).
Открытие последнего проекта не запускает синхронизацию автоматически.

Кнопка «Новый проект» создаёт конфигурацию и импортирует комплект клиента.
Укажите HTTPS-адрес, новую папку проекта и полученную от сервера папку с ca.pem
и token.txt. Можно выбрать существующую папку файлов или оставить поле пустым:
тогда используется новая shared внутри проекта. Существующие файлы не изменяются
при настройке. Папка проекта должна находиться вне выбранной папки файлов на
том же томе; исходный комплект реквизитов также не должен находиться среди
синхронизируемых файлов. После создания отдельно проверьте соединение и план.

«Импорт реквизитов» работает для открытого проекта с пустым каталогом реквизитов,
где token.txt и ca.pem лежат рядом. Он не заменяет существующие сертификаты и
не меняет конфигурацию. Для ротации используйте отдельную проверенную процедуру.
При sync.lock импорт блокируется. Если создание прервалось из-за ошибки записи,
частичный проект сохраняется для проверки, а не удаляется автоматически.

## Доступные действия

- Проверка соединения через существующий HTTPS doctor.
- Предварительный план без изменения файлов.
- Таблица изменений и конфликтов с поиском по пути или действию.
- Отдельная вкладка сохранённых конфликтов и выбор версии файла.
- Список локальных резервных копий, проверка целостности и экспорт.
- Один проход двусторонней синхронизации.
- Постоянная работа с локальным наблюдением и периодической сверкой.
- Штатная остановка после текущего прохода, без удаления блокировок вручную.
- Статус, прогресс текущего файла, результаты прохода и журнал в окне.

GUI одновременно выполняет одну операцию. Во время работы открыть другой проект
или запустить вторую операцию нельзя. Закрытие окна предлагает остановить работу
и ждёт завершения потока; сетевые ожидания ограничены request_timeout проекта,
но это не ограничение длительности всей операции. Статус относится к текущему
процессу GUI, последний проект запоминается через QSettings. Токен не сохраняется
в настройках окна.

Кнопка постоянной работы явно выбирает непрерывный режим, независимо от watch
в TOML. dry_run в конфигурации запрещает изменяющие действия GUI. log_file пока
не поддерживается для синхронизации через GUI: используйте CLI либо отдельную
конфигурацию без log_file. Журнал GUI ограничен 800 блоками и не сохраняется на диск.

## Ограничения первой версии

Редактирование настроек существующего проекта ещё не реализовано. Диагностика пока показывается
структурированным текстом в журнале. План — снимок на момент проверки, не команда
на применение сохранённого списка. После запуска или новой проверки старый план
помечается как потенциально устаревший. Нет трея, автозапуска и автономной сборки exe.
Не запускайте одновременно CLI sync и GUI для одного состояния. Stale-lock и
pending требуют ручной проверки по [SYNC.md](../SYNC.md), GUI их не удаляет.

## Разрешение конфликтов

Остановите постоянную синхронизацию, откройте «Конфликты» и нажмите «Обновить».
Список читается из последнего сохранённого отчёта; это не новая сетевая проверка.
Если конфликта ещё нет в отчёте, выполните один проход синхронизации. Выберите
строку и локальную/серверную версию либо «Сохранить обе». В последнем случае
локальная версия копируется под новым относительным именем, а серверная становится
основной; родительская папка копии должна существовать. Имя не должно быть занято
на любой стороне. После разрешения выполните обычную сверку для проверки результата.

Диалог подтверждает **полный проход синхронизации**, поэтому могут согласовываться
и другие файлы. Выбор версии с состоянием «Удалён / отсутствует» распространяет удаление.
Ядро проверяет сохранённые снимки: если версия уже изменилась, выбор отклоняется.
В этом случае повторите синхронизацию и рассмотрите новый конфликт. Конфликты имён,
каталогов и записи без пригодного снимка могут требовать ручного решения.

## Резервные копии

«Обновить» читает список локального recovery; наличие файла не означает, что его
хеш уже проверен. «Проверить целостность» отдельно показывает проверенные,
отсутствующие, повреждённые копии и ошибки метаданных. Полные значения путей,
хешей и идентификаторов доступны в подсказках ячеек таблиц.

Для экспорта выберите пригодную строку и **новый файл вне синхронизируемой папки
и каталога состояния**. Ядро снова проверяет SHA-256, не перезаписывает существующий
файл и оставляет backup на месте. Экспорт — получение отдельной копии, не откат
baseline или автоматический ремонт pending. При sync.lock экспорт блокируется.
Чтение списка, проверка и экспорт не требуют сети, токена или сертификата сервера;
конфигурация проекта при этом должна быть корректной. Серверный recovery в этой
вкладке не отображается.

Все действия выполняются одним рабочим потоком; новые операции и смена проекта
недоступны до его завершения. Остановка проверки хешей или экспорта, как и
синхронизации, ожидает окончания текущей операции.

## Проверки

Семь Qt-тестов проверяют работу вне главного потока, запрет второй операции,
штатную остановку и закрытие соединения, сокрытие токена в ошибке, повторный запуск,
закрытие окна, сохранение текущего проекта при неверной конфигурации,
защиту dry_run и отображение состояния передачи.

```sh
python -m unittest discover -s tests -p "test_gui*.py" -v
```

Тесты работают с offscreen-платформой Qt и пропускаются без PySide6. Сетевой smoke
на Windows с Linux-сервером также проверяет doctor, план без baseline, upload,
download серверного изменения, освобождение lock при остановке и повторный запуск.
Автоматические проверки окна не заменяют ручную проверку на рабочем столе Linux,
включая масштабирование и платформенные диалоги. Архитектура следующего этапа:
[GUI_INTEGRATION.md](GUI_INTEGRATION.md).

Windows GUI → Linux-сервер прошёл все 6 проверок, включая передачу обратно и
освобождение блокировки. Временный сервер остановлен, правило UFW удалено.
